<rule_activation id="0999e334-837c-4cbb-81c0-f6326f7b9f6b" title="Implement Cache Layer Pattern for Public API Data Management: Cache Implementations Provide" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Cache layer implementations for public APIs MUST provide explicit cache invalidation mechanisms to prevent serving stale data and maintain consistent, efficient data management across all public API surfaces.
</rule_activation>

### Rules

- **R-CACHE-001** MUST: Cache implementations MUST provide explicit cache invalidation mechanisms to prevent serving stale data.

### Verify

```bash
# Count cache-related implementations using Map or WeakMap
grep -r "cache" packages/svelte/src/internal/client/ --include="*.js" | grep -E "(Map|WeakMap|cache)" | wc -l

# Count documented cache strategies using JSDoc tags
grep -r "@cached\|@nocache" packages/svelte/src/ --include="*.js" | wc -l

# Run cache-specific test suite
npm test -- --grep "cache" 2>&1 | grep -E "(passing|failing)"
```

**Accept when:**
- All public API methods performing data retrieval or computation have documented cache strategies (either @cached or @nocache with rationale)
- Cache invalidation tests exist for all cached API methods with at least 80% coverage of invalidation scenarios
- Development mode cache debugging is enabled and logs cache hit/miss metrics for performance analysis

<enforcement>
Claude Code MUST NOT skip or defer verification. All public API methods must be audited for cache strategy documentation, and cache invalidation test coverage must meet the 80% threshold before acceptance.
</enforcement>
