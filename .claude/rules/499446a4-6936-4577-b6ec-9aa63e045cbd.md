<rule_activation id="499446a4-6936-4577-b6ec-9aa63e045cbd" title="Implement Cache Layer Pattern for Public API Data Management: Cache Keys Deterministically" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Cache layer implementation is a foundational data management strategy for public APIs in client-side frameworks, ensuring consistent, efficient, and maintainable data retrieval mechanisms.
</rule_activation>

### Rules

- **R-CACHE-001** MUST: Cache keys MUST be deterministically generated based on input parameters to ensure consistent cache hit/miss behavior.

### Verify

```bash
# Count cache-related implementations in client modules
grep -r "cache" packages/svelte/src/internal/client/ --include="*.js" | grep -E "(Map|WeakMap|cache)" | wc -l

# Count documented cache strategies in codebase
grep -r "@cached\|@nocache" packages/svelte/src/ --include="*.js" | wc -l

# Run cache-specific test suite
npm test -- --grep "cache" 2>&1 | grep -E "(passing|failing)"
```

**Accept when:**
- All public API methods performing data retrieval or computation have documented cache strategies (either @cached or @nocache with rationale)
- Cache invalidation tests exist for all cached API methods with at least 80% coverage of invalidation scenarios
- Development mode cache debugging is enabled and logs cache hit/miss metrics for performance analysis
- Cache keys are generated using consistent hashing strategy (JSON.stringify or custom serialization)
- Cache storage uses Map or WeakMap with appropriate reference semantics for data lifecycle

<enforcement>
Claude Code MUST NOT skip or defer verification. All public API methods must have documented cache strategies before code is accepted. Cache invalidation test coverage must meet 80% threshold. Performance benchmarks must track cache hit rates and flag regressions below 70% threshold.
</enforcement>
