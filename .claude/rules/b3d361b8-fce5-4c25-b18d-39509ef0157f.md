<rule_activation id="b3d361b8-fce5-4c25-b18d-39509ef0157f" title="Adopt Modular Public API Export Pattern with Explicit Re-exports: Internal Implementation Files" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching entry points and public API modules in the framework.
</rule_activation>

### Rules

- **R-API-001** MUST: Internal implementation files MUST reside in separate directories from public entry points (e.g., internal/, compiler/utils/)
- **R-API-002** MUST: All public entry point files (index.js, index-server.js, index-client.js) contain only re-export statements without implementation logic
- **R-API-003** MUST: Public APIs intended for external use MUST be exported through designated entry point files
- **R-API-004** SHOULD: Add JSDoc @public tags to all functions/classes intended for external use and @internal tags for private APIs
- **R-API-005** SHOULD: Organize internal implementation in subdirectories (internal/, compiler/, etc.) that are not directly accessible to consumers
- **R-API-006** SHOULD: Use build-target-specific entry points (index-server.js, index-client.js) for environment-specific APIs
- **R-API-007** MAY: Configure package.json exports field to explicitly allow only entry point imports and block direct internal module access

### Verify

```bash
# Count re-exports from internal modules in entry points
grep -r "export.*from.*internal" packages/*/src/index*.js | wc -l

# Find entry point files that don't contain exports
find packages/*/src -name 'index*.js' -exec grep -L 'export.*from' {} \;

# Verify build succeeds and produces output
npm run build && node -e "const api = require('./dist'); console.log(Object.keys(api).length > 0)"
```

**Accept when:**
- All public entry point files contain only re-export statements without implementation logic
- Internal implementation files are organized in separate directories from entry points
- Build succeeds and produces separate bundles for different targets (client, server, dev) when applicable
- Public API documentation can be generated solely from entry point files
- No direct imports from internal modules are detected in external-facing code

<enforcement>
Claude Code MUST verify entry point structure and export patterns before accepting changes. CI checks MUST fail if entry points contain implementation logic beyond re-exports. Pull requests MUST be blocked if new public APIs are not exported through entry points.
</enforcement>
