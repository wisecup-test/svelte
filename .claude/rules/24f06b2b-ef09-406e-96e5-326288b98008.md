These rules are ALWAYS ACTIVE for all files matching `**/*`. All public API endpoints that perform data retrieval or computation MUST implement a cache layer to prevent redundant operations.
</rule_activation>

### Rules

- **R-CACHE-001** MUST: All public API endpoints that perform data retrieval or computation MUST implement a cache layer to prevent redundant operations.
- **R-CACHE-002** MUST: Use Map or WeakMap for cache storage depending on whether strong or weak references are appropriate for the cached data lifecycle.
- **R-CACHE-003** MUST: Implement cache key generation using a consistent hashing strategy (e.g., JSON.stringify for object parameters, or custom serialization for complex types).
- **R-CACHE-004** SHOULD: Provide a development mode flag that logs cache hits/misses and warns about potential invalidation issues.
- **R-CACHE-005** SHOULD: Consider implementing a cache decorator or higher-order function to standardize cache layer application across API methods.
- **R-CACHE-006** SHOULD: Document cache behavior in API method signatures using JSDoc tags (@cached, @cachekey, @cachettl) for developer clarity.
- **R-CACHE-007** MUST: Enforce cache size limits with LRU or similar eviction policies to prevent memory leaks from unbounded cache growth.
- **R-CACHE-008** MUST: Implement comprehensive test coverage for cache invalidation scenarios, use cache versioning, and provide development mode warnings for potential stale data.

### Exceptions

- **EXC-001**: API methods explicitly require fresh data on every invocation for security or compliance reasons.
- **EXC-002**: Memory constraints in embedded or resource-limited environments make caching infeasible.

### Verify

```bash
# Count cache implementations in client modules
grep -r "cache" packages/svelte/src/internal/client/ --include="*.js" | grep -E "(Map|WeakMap|cache)" | wc -l

# Count documented cache strategies
grep -r "@cached\|@nocache" packages/svelte/src/ --include="*.js" | wc -l

# Run cache-specific tests
npm test -- --grep "cache" 2>&1 | grep -E "(passing|failing)"
```

**Accept when:**
- All public API methods performing data retrieval or computation have documented cache strategies (either @cached or @nocache with rationale).
- Cache invalidation tests exist for all cached API methods with at least 80% coverage of invalidation scenarios.
- Development mode cache debugging is enabled and logs cache hit/miss metrics for performance analysis.
- Cache hit rates remain above 70% threshold in performance benchmarks.
