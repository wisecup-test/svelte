<rule_activation id="fd83fde4-601d-408a-a04b-15ba99b0e0d2" title="Adopt Modular Public API Export Pattern with Explicit Re-exports: Development Specific Isolated" applies_to="**/*">
These rules are ALWAYS ACTIVE for all framework entry points, public API modules, compiler utilities, and runtime functions intended for external consumption.
</rule_activation>

### Rules

- **R-API-001** SHOULD: Development-specific APIs SHOULD be isolated in separate modules (e.g., dev/ subdirectories) and conditionally exported.
- **R-API-002** MUST: All public entry point files (index.js, index-server.js, index-client.js) MUST contain only re-export statements without implementation logic.
- **R-API-003** MUST: Internal implementation files MUST be organized in separate directories (internal/, compiler/, etc.) from entry points.
- **R-API-004** SHOULD: All functions and classes intended for external use SHOULD be tagged with JSDoc @public annotations.
- **R-API-005** SHOULD: All private APIs SHOULD be tagged with JSDoc @internal annotations.
- **R-API-006** MUST: Build-target-specific entry points (server vs client) MUST be configured to enable tree-shaking and optimal bundle sizes.
- **R-API-007** MUST: New public APIs MUST be exported through entry points before being considered part of the public API surface.
- **R-API-008** SHOULD: package.json exports field SHOULD be configured to explicitly allow only entry point imports and block direct internal module access.

### Verify

```bash
# Count re-exports from internal modules in entry points
grep -r "export.*from.*internal" packages/*/src/index*.js | wc -l

# Find entry point files that lack export statements
find packages/*/src -name 'index*.js' -exec grep -L 'export.*from' {} \;

# Verify build succeeds and produces output
npm run build && node -e "const api = require('./dist'); console.log(Object.keys(api).length > 0)"

# Verify entry points contain only re-exports
grep -E "^[^/]*implementation|^[^/]*logic" packages/*/src/index*.js
```

**Accept when:**
- All public entry point files contain only re-export statements without implementation logic
- Internal implementation files are organized in separate directories from entry points
- Build succeeds and produces separate bundles for different targets (client, server, dev) when applicable
- Public API documentation can be generated solely from entry point files
- No direct imports from internal modules are detected in external-facing code
- All intended public APIs are exported through entry points

<enforcement>
Claude Code MUST verify entry point structure and export patterns before accepting changes. CI checks MUST validate that entry points contain only re-exports. Pull requests MUST be blocked if new public APIs are not exported through entry points. Linter warnings for direct internal module imports MUST be elevated to errors.
</enforcement>
