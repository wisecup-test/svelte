<rule_activation id="875177da-f18b-42bf-a018-35826f1427a8" title="Adopt Modular Public API Export Pattern with Explicit Re-exports: Build Target Specific" applies_to="**/*">
These rules are ALWAYS ACTIVE for all framework entry points, public API modules, compiler utilities, and runtime functions intended for external consumption.
</rule_activation>

### Rules

- **R-API-001** SHOULD: Build-target-specific entry points SHOULD use descriptive suffixes (e.g., -server, -client) to indicate their intended environment.
- **R-API-002** MUST: All public entry point files MUST contain only re-export statements without implementation logic.
- **R-API-003** MUST: Internal implementation files MUST be organized in separate directories (internal/, compiler/, etc.) from entry points.
- **R-API-004** MUST: New public APIs MUST be exported through entry points before merging to main.
- **R-API-005** SHOULD: All functions/classes intended for external use SHOULD be tagged with JSDoc @public; private APIs SHOULD use @internal tags.
- **R-API-006** MUST: Direct imports from internal modules in public-facing code MUST be detected and blocked by linting rules.
- **R-API-007** SHOULD: Entry point files SHOULD use named exports for all re-exported public APIs.
- **R-API-008** SHOULD: package.json exports field SHOULD be configured to explicitly allow only entry point imports and block direct internal module access.

### Verify

```bash
# Count re-exports from internal modules in entry points
grep -r "export.*from.*internal" packages/*/src/index*.js | wc -l

# Find entry point files that lack export statements
find packages/*/src -name 'index*.js' -exec grep -L 'export.*from' {} \;

# Verify build succeeds and produces output
npm run build && node -e "const api = require('./dist'); console.log(Object.keys(api).length > 0)"
```

**Accept when:**
- All public entry point files contain only re-export statements without implementation logic
- Internal implementation files are organized in separate directories from entry points
- Build succeeds and produces separate bundles for different targets (client, server, dev) when applicable
- Public API documentation can be generated solely from entry point files
- No direct imports from internal modules are detected in public-facing code
- All intended public APIs are exported through entry points

<enforcement>
Claude Code MUST NOT skip or defer verification. All rules in this activation MUST be checked before accepting changes to entry points, public APIs, or internal module organization. Violations MUST block CI builds and pull requests.
</enforcement>
