<rule_activation id="b7cba152-c36e-4565-8be1-74d1c79fc5ea" title="Implement Cache Layer Pattern for Public API Data Management: Cache Implementations Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching `**/*`. Cache layer implementations for public APIs must follow standardized patterns to ensure consistent, efficient, and secure data management across client-side frameworks.
</rule_activation>

### Rules

- **R-CACHE-001** MUST_NOT: Cache implementations MUST NOT cache sensitive user data without explicit encryption or secure storage mechanisms.
- **R-CACHE-002** MUST: All public API methods performing data retrieval or computation MUST have documented cache strategies (either @cached or @nocache with rationale).
- **R-CACHE-003** MUST: Cache invalidation tests MUST exist for all cached API methods with at least 80% coverage of invalidation scenarios.
- **R-CACHE-004** SHOULD: Use Map or WeakMap for cache storage depending on whether strong or weak references are appropriate for the cached data lifecycle.
- **R-CACHE-005** SHOULD: Implement cache key generation using a consistent hashing strategy (e.g., JSON.stringify for object parameters, or custom serialization for complex types).
- **R-CACHE-006** SHOULD: Provide a development mode flag that logs cache hits/misses and warns about potential invalidation issues.
- **R-CACHE-007** SHOULD: Consider implementing a cache decorator or higher-order function to standardize cache layer application across API methods.
- **R-CACHE-008** SHOULD: Document cache behavior in API method signatures using JSDoc tags (@cached, @cachekey, @cachettl) for developer clarity.
- **R-CACHE-009** MAY: Enforce cache size limits with LRU or similar eviction policies to prevent unbounded cache growth in long-running applications.

### Verify

```bash
# Count cache-related implementations in client modules
grep -r "cache" packages/svelte/src/internal/client/ --include="*.js" | grep -E "(Map|WeakMap|cache)" | wc -l

# Verify cache documentation tags are present
grep -r "@cached\|@nocache" packages/svelte/src/ --include="*.js" | wc -l

# Run cache-specific test suite
npm test -- --grep "cache" 2>&1 | grep -E "(passing|failing)"
```

**Accept when:**
- All public API methods performing data retrieval or computation have documented cache strategies (either @cached or @nocache with rationale)
- Cache invalidation tests exist for all cached API methods with at least 80% coverage of invalidation scenarios
- Development mode cache debugging is enabled and logs cache hit/miss metrics for performance analysis
- Cache hit rates remain above 70% threshold in performance benchmarks
- No new public API methods lack @cached or @nocache documentation
