These rules are ALWAYS ACTIVE for all files matching `**/*`. Cache layer implementations for public APIs SHOULD expose metrics or debugging hooks for cache hit/miss rates in development mode to ensure consistent, efficient, and maintainable data management across all public API surfaces.
</rule_activation>

### Rules

- **R-CACHE-001** SHOULD: Cache implementations SHOULD expose metrics or debugging hooks for cache hit/miss rates in development mode.

### Verify

```bash
# Count cache-related implementations in client modules
grep -r "cache" packages/svelte/src/internal/client/ --include="*.js" | grep -E "(Map|WeakMap|cache)" | wc -l

# Count @cached/@nocache documentation tags
grep -r "@cached\|@nocache" packages/svelte/src/ --include="*.js" | wc -l

# Run cache-specific tests
npm test -- --grep "cache" 2>&1 | grep -E "(passing|failing)"
```

**Accept when:**
- All public API methods performing data retrieval or computation have documented cache strategies (either @cached or @nocache with rationale)
- Cache invalidation tests exist for all cached API methods with at least 80% coverage of invalidation scenarios
- Development mode cache debugging is enabled and logs cache hit/miss metrics for performance analysis

<enforcement>
Claude Code MUST verify all three acceptance criteria before approving changes to public API methods. Cache strategy documentation and invalidation test coverage are mandatory. Performance regression alerts triggering below 70% cache hit rate threshold require investigation.
</enforcement>
